## 💡 為什麼需要這個 Skill？

許多人在請 AI 教學一個陌生領域時，常遇到以下痛點：
- **迷失在細節中**：AI 一開口就丟出一大堆專有名詞與片段細節，缺乏全域脈絡。
- **單向灌輸與灌水湊字**：死記百科全書式解答，或因生硬字數限制而硬塞杜撰數據、強套無關概念。
- **長對話遺忘與截斷**：多輪對話後，前面學過的重點因 Context Compaction 被壓縮淡忘；匯出講義時模型更常因輸出長度截斷死檔。

**Knowledge Map Learning** 徹底解決了這些問題：
摒棄花拳繡腿的繪圖包袱與生硬字數配額，**以「清楚、具體、可推理」的講義品質規格把關教學深度**。先給你清晰的演化故事大綱（見森林），再帶你走過每個核心節點（見樹木），並透過**逐回合實體落盤**與**雙軌模板編譯**，打造堅不可摧的長對話沉浸學習體驗。

## ✨ 核心特色

1. **🚀 零摩擦冷啟動（Zero-Friction Start）**  
   主題具體明確時，第一回合直接給出結構化脈絡大綱，並**同回合無縫展開 M1-1 講義與第一道開放思考題**，不浪費任何對話輪次等待確認，立即進入專注心流。

2. **🧠 通用四層認識論 ＆ 跨領域相容性**  
   完美兼顧**「單一 API、演算法家族、數學定理、人文理論」**四類主題，自然融入四層深度架構：
   - **核心問題與背景痛點**：剖析核心研究問題與背景困境，不杜撰歷史或單一因果
   - **直覺心智模型**：具象比喻打破抽象藩籬
   - **機制／證據／推導**：底層數據流、數學推導、因果傳導或實證證據
   - **適用條件與邊界限制**：前提邊界、取捨代價、模型限制與易混淆概念

3. **📐 講義品質規格（取代生硬字數配額）**  
   拒絕為湊字數而灌水或編造數據，改以五大實質品質條件與「理解剃刀」嚴格把關每一節課的含金量。

4. **🤝 思維磨刀石（思維夥伴，非考官批改）**  
   課後以**遷移思考題**啟發心智模型。即使回答「不知道」或「跳過」，導師也會主動一針見血點破核心盲點（Aha! moment），絕不施加負面標籤或輸出「待複習：無」等後台雜訊。

5. **💾 逐回合即時落盤（Per-Turn Flush，抗上下文壓縮）**  
   講義回合存講義、問答回合存師生 Q&A 心流。以本地磁碟實體 Markdown 為**唯一資料來源（Single Source of Truth）**，降低長對話上下文壓縮造成的遺失風險。

6. **⚡ 模板組裝編譯 ＆ 雙軌降級容錯（零 Token 截斷）**  
   結課匯出時，預設由內建 Python 腳本（標準庫、零外部依賴）自動讀取磁碟筆記注入自包含現代化 HTML 模板；**若環境無 Python 則自動切換 Agent 直出降級**，完全杜絕長文截斷死檔風險。

7. **🛡️ 檔案防覆蓋與環境自適應雙軌交付**  
   支援續學智慧偵測、檔名安全過濾與時間戳防覆蓋機制；產出時同時提供宿主支援之可點擊預覽連結與本機實體絕對路徑。

## 📏 講義品質規格與理解剃刀

本技能徹底廢除死板的固定字數限制，改以**「內容是否清楚、具體、可推理」**作為真實品質標準：

### 1. 首次講義五大品質條件（自然融入講解）
- **核心主張清楚**：至少提出一個可檢驗或可論證的主張，交代成立前提，以及機制、證據或推導；避免只說「很重要」。
- **有具體支撐**：至少提供一個具體案例、推演、操作結果或可核對的證據。數字不是必需品；使用數字時說明條件，涉及時效性事實時查證，不為達標編造資料。
- **指出理解邊界**：說明適用條件、常見誤判、易混淆概念，或前提改變後的反例；不強迫替成立的定理製造反例。
- **交代代價或限制**：技術與策略說明採用成本及權衡；理論與人文主題說明模型、證據或詮釋的限制，不硬套效能與維護成本。
- **設計遷移思考題**：改變案例、情境或前提，要求預測、比較、診斷或解釋理由，不能只靠抄寫本節原句作答。

### 2. 長度、追問與自檢準則
- **長度由理解需要決定**：不設字數配額或違規門檻。
- **窄節點 vs 寬節點**：窄節點講清核心即可，不得為增加篇幅重複解釋；寬節點在開頭交代本節範圍與其餘內容所屬節點，包含多個可獨立學習的概念時優先拆節點。
- **追問機制**：後續追問只補充缺少的理解，不強制重走完整架構。
- **資訊熵與理解剃刀**：*「刪除此句後，若準確性、理解、推理銜接與記憶都不受影響，就刪除。」* 僅保留有助理解的比喻與必要重述。

## 🔄 三階段學習流程

```
┌─────────────────────────────────────────────────────────────┐
│ 階段一：脈絡全景圖與冷啟動 (Zero-Friction Start)             │
│ • 生成 Markdown 階層大綱與節點進度清單                      │
│ • 同回合直接無縫展開 M1-1 深度精講與遷移思考題              │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 階段二：分支深度精講與即時落盤 (Per-Turn Flush)              │
│ • 貫穿通用四層認識論與五大講義品質規格                      │
│ • 遷移式情境思考題 ＆ 蘇格拉底式引導                         │
│ • 講義與探討 Q&A 逐回合即時追加至實體 Markdown               │

│ • 執行匯出前強制補存                                        │
│ • 調用 build_notes.py（或無 Python 時自動降級生成手冊）      │
│ • 交付宿主支援之可點擊預覽連結與本機實體檔案路徑             │
└─────────────────────────────────────────────────────────────┘
```

## 📖 輸出格式範例

### 1. 階段一：學習脈絡全景圖與進度清單

```markdown
### 🧭 學習脈絡全景圖

- **M1 容器虛擬化基礎**：【演化起點】傳統虛擬機的資源隔離代價與進程級隔離突破
  - `M1-1` 容器 vs 虛擬機：Namespace 與 Cgroups 隔離哲學
  - `M1-2` 映像檔分層架構：UnionFS 與 Copy-on-Write 機制
- **M2 服務編排與網路**：【深度機制】單機到多機叢集的調度演化
  - `M2-1` 容器網路模型：Bridge, Host 與 Overlay 封包路徑推導

| ID | 節點名稱 | 一句話核心價值 | 狀態 |
|---|---|---|---|
| M1-1 | 容器 vs 虛擬機 | 釐清進程隔離與硬體虛擬化之本質邊界與取捨 | 進行中 |
| M1-2 | 映像檔分層架構 | 理解 CoW 機制與映像檔建置策略 | 未開始 |
| M2-1 | 容器網路模型 | 掌握虛擬網卡與 iptables 轉發因果鏈條 | 未開始 |
```

### 2. 階段二：單節點深度精講（融合四層認識論與品質規格）

```markdown
> 🧭 進度 1/3｜當前 M1-1：容器 vs 虛擬機

### 容器虛擬化基礎 > 容器 vs 虛擬機（M1-1）

#### 1. 核心問題與背景痛點（Core Problem & Context）
在硬體虛擬化架構下，每個應用執行個體都必須捆綁完整的 Guest OS Kernel，造成記憶體與啟動時間的固定開銷。當系統需要在單機高密度部署數十個短生命週期的服務時，是否能跳過硬體模擬，直接由同一個作業系統核心提供隔離環境？

#### 2. 直覺心智模型（Intuitive Mental Model）
虛擬機如同各自擁有獨立地基、水電總開關的獨棟透天厝；容器則像共用同一棟大樓地基與主幹管線（Host Kernel）的獨立套房，房客雖有各自的門鎖與電表，但若大樓主結構受損，所有套房都會受波及。

#### 3. 機制／證據／推導（Mechanism / Evidence / Derivation）
Linux 容器並非獨立的虛擬機器，而是受兩項核心機制約束的一般主機進程：
- **Namespaces（視角隔離）**：透過 `clone()` 系統呼叫帶入 `CLONE_NEWPID`、`CLONE_NEWNET` 等旗標，使進程在容器內看到獨立的 PID 1 與專屬網路介面，但在宿主機上執行 `ps aux` 仍可直接觀測到該進程。
- **Cgroups（資源限制）**：在 `/sys/fs/cgroup` 階層中限制該進程群組可消耗的 CPU 配額與記憶體上限，防止單一進程觸發全機 OOM。

#### 4. 適用條件與邊界限制（Conditions & Limitations）
- **理解邊界與常見誤判**：容器提供的是「環境與資源隔離」而非「強安全沙箱」。一旦共用 Kernel 存在提權漏洞，容器內進程即可逃逸至宿主機。此外，Linux 容器依賴 Linux Kernel 系統呼叫，無法在未開啟輕量 VM 的情況下於原生 Windows Kernel 直接執行 Linux 容器。
- **採用代價與權衡**：換取極低啟動延遲與高密度的代價，是犧牲了不同作業系統核心的異質相容性與硬體級安全邊界。

#### 5. 啟發性開放思考題（Thinking Probe）
假設你需要為一個線上程式評測系統（Online Judge）設計執行沙箱，允許全球匿名使用者上傳任意 C++ 程式碼並編譯執行。若僅使用預設的 Docker 容器進行隔離，會面臨什麼核心風險？你會如何調整隔離架構或前提條件來防範？
```

## 🎮 常用互動指令表

在對話過程中，你可以隨時輸入以下指令來控制學習節奏：

| 指令 | 說明 |
|---|---|
| `地圖`／`大綱` | 重新輸出完整知識脈絡大綱與節點清單（含當前進度狀態） |
| `下一節點`／`繼續` | 順暢進入下一個未完成節點 |
| `跳至 M<ID>`／`講 M<ID>` | 非線性跳轉至指定節點，系統自動記住原進度錨點 |
| `返回進度` | 返回最近一次跳讀前的節點 |
| `跳過` | 導師簡述核心精要，標記流程完成後直接推進 |
| `深入`／`延伸` | 針對當前節點做更極致的實戰邊界或原始碼/理論層級深挖 |
| `調整架構` | 靈活增刪模組或節點，保留既有編號與已記錄筆記 |
| `一次全部給我` | 切換為精簡模式，一次性輸出所有章節精講 |
| `結束`／`匯出` | 進入第三階段，自動編譯輸出 HTML 互動手冊與全量 Markdown 筆記 |

## 🖥️ 第三階段：編譯 HTML 互動手冊

完成學習後，系統將自動調用內建的 Python 組裝編譯器（或無 Python 時自動降級）：
```bash
python "<目前 SKILL.md 所在目錄>/scripts/build_notes.py" "<notes_path 的實際絕對路徑>"
```

### 產出的 HTML 互動手冊具備以下特色：
- 🔍 **DOM TreeWalker 即時搜尋**：快速過濾章節與內文關鍵字。
- 🧭 **Scrollspy 滾動監聽導覽**：側邊欄目錄隨閱讀進度自動高亮對應章節。
- 🌓 **深淺色主題切換**：自動適應系統主題，支援一鍵切換深色/淺色閱讀模式。
- 🖨️ **@media print 列印排版**：最佳化列印樣式，可直接一鍵另存為乾淨的 PDF 文件。
- 📦 **零外部依賴、完全自包含**：單一 HTML 檔案，離線可直接雙擊瀏覽。

## 📥 安裝指南

### 在 Antigravity 中使用（推薦）
將此 `knowledge-map-learning` 資料夾直接複製到 Antigravity 全域技能目錄：
- **Windows (PowerShell)**：
  ```powershell
  Copy-Item -Path "D:\develop\AI\mySkill\knowledge-map-learning" -Destination "$HOME\.gemini\config\skills\knowledge-map-learning" -Recurse -Force
  ```
- **macOS / Linux**：
  ```bash
  cp -r knowledge-map-learning "$HOME/.gemini/config/skills/knowledge-map-learning"
  ```
複製完成後，Antigravity 將**即刻自動偵測並啟用**本技能！
