## 💡 為什麼需要這個 Skill？

許多人在請 AI 教學一個陌生領域時，常遇到以下痛點：
- **迷失在細節中**：AI 一開口就丟出一大堆專有名詞與片段細節，缺乏全域脈絡。
- **單向灌輸與假性理解**：死記百科全書式解答，缺乏直覺心智模型與思維驗證。
- **長對話遺忘與截斷**：多輪對話後，前面學過的重點因 Context Compaction 被壓縮淡忘；匯出講義時模型更常因輸出長度截斷死檔。

**Knowledge Map Learning** 徹底解決了這些問題：
摒棄花拳繡腿的繪圖包袱與死板打卡，**專注於教學深度、底層運作本質與思維啟發**。先給你清晰的演化故事大綱（見森林），再帶你走過每個核心節點（見樹木），並透過**逐回合實體落盤**與**模板腳本編譯**，打造堅不可摧的長對話沉浸學習體驗。

## ✨ 核心特色

1. **🚀 零摩擦冷啟動（Zero-Friction Start）**  
   主題具體明確時，第一回合直接給出結構化脈絡大綱，並**同回合無縫展開 M1-1 講義與第一道開放思考題**，不浪費任何對話輪次等待確認，立即進入專注心流。

2. **🧠 通用四層認識論（400～800 字深度精講）**  
   跨越技術、人文與社科學科界限，每節點嚴格貫穿四層深度架構：
   - **核心問題與痛點**：誕生背景與欲解決的本質反常
   - **直覺心智模型**：具象比喻打破抽象藩籬
   - **機制／證據／推導**：底層數據流、因果傳導或 ASCII 架構圖
   - **適用條件與邊界限制**：反模式、代價與認知地雷

3. **🤝 思維磨刀石（思維夥伴，非考官批改）**  
   課後思考題以啟發心智模型為核心，進行平等的深層探討。即使回答「不知道」或「跳過」，導師也會主動一針見血點破核心盲點（Aha! moment），絕不施加負面標籤或輸出「待複習：無」等後台雜訊。

4. **💾 逐回合即時落盤（Per-Turn Flush，抗上下文壓縮）**  
   講義回合存講義、問答回合存師生 Q&A 心流。以本地磁碟實體 Markdown 為**唯一真理源（Single Source of Truth）**，免疫於長對話上下文壓縮與內容丟失。

5. **⚡ 固定模板＋腳本編譯（零 Token 截斷）**  
   結課匯出時，由內建 Python 腳本（標準庫、零外部依賴）自動讀取磁碟筆記注入自包含現代化 HTML 模板，**AI 無需重複手寫輸出**，徹底杜絕截斷死檔問題。

6. **🛡️ 檔案防覆蓋與環境自適應雙軌交付**  
   支援續學智慧偵測、檔名安全過濾與時間戳防覆蓋機制；產出時同時提供工作區相對連結與本機實體絕對路徑。

└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 階段二：分支深度精講與即時落盤 (Per-Turn Flush)              │

│ • 開放式情境思考題 ＆ 蘇格拉底式引導                         │

## 📖 輸出格式範例

### 1. 階段一：學習脈絡全景圖與進度清單

```markdown
### 🧭 學習脈絡全景圖

- **M1 容器虛擬化基礎**：【演化起點】傳統虛擬機的沉重負擔與進程隔離突破
  - `M1-1` 容器 vs 虛擬機：Namespace 與 Cgroups 隔離哲學
  - `M1-2` 映像檔分層架構：UnionFS 與唯讀層最佳化
- **M2 服務編排與網路**：【深度機制】單機到多機叢集的調度演化
  - `M2-1` 容器網路模型：Bridge, Host 與 Overlay 本質推導

| ID | 節點名稱 | 一句話核心價值 | 狀態 |
|---|---|---|---|
| M1-1 | 容器 vs 虛擬機 | 釐清進程隔離與完整 OS 模擬之本質差異 | 進行中 |
| M1-2 | 映像檔分層架構 | 理解 CoW 機制與映像檔建置最佳化 | 未開始 |
| M2-1 | 容器網路模型 | 掌握虛擬網卡與 iptables 轉發核心鏈條 | 未開始 |
```

### 2. 階段二：單節點 400～800 字四層精講

```markdown
> 🧭 進度 1/3｜當前 M1-1：容器 vs 虛擬機

### 容器虛擬化基礎 > 容器 vs 虛擬機（M1-1）

#### 1. 核心問題與背景痛點（Core Problem & Context）
在硬體虛擬化時代，為了運行單一微服務，工程師必須為每台 VM 配置完整的 Guest OS，帶來龐大的記憶體佔用與數分鐘的開機延遲...

#### 2. 直覺心智模型（Intuitive Mental Model）
如果說虛擬機就像買下一棟棟獨立建造、自帶地基與水電管線的透天別墅；容器則像是同一棟現代公寓大廈裡的獨立套房，共用大樓的地基與管線（Host Kernel），但每個房間門牌與門鎖各自獨立...

#### 3. 機制／證據／推導（Mechanism / Evidence / Derivation）
Linux 容器本質上只是一個受約束的一般進程。底層核心依賴兩大基石：
- **Namespaces**：負責「視角隔離」（PID、Mount、Network 等），讓進程以為自己擁有全世界。
- **Cgroups**：負責「資源配額」（CPU 週期、Memory 限制），防止個別進程耗盡主機資源。

#### 4. 適用條件與邊界限制（Conditions & Limitations）
- **致命邊界**：容器並非硬體安全沙箱，所有容器共用同一個 Host OS Kernel。若核心發生漏洞（如 Dirty COW），可能引發逃逸攻擊。
- **常見地雷**：將容器當作持久化虛擬機使用，在容器內部存放重要狀態。

#### 5. 啟發性開放思考題（Thinking Probe）
若今天公司要運行一個高度合規、需嚴格防止跨租戶特權滲透的金融核心交易系統，你會選擇單純的容器隔離，還是虛擬機（或 MicroVM）？為什麼？
```

## 🎮 常用互動指令表

在對話過程中，你可以隨時輸入以下指令來控制學習節奏：

| 指令 | 說明 |
|---|---|
| `地圖`／`大綱` | 重新輸出完整知識脈絡大綱與節點清單（含當前進度狀態） |
| `下一節點`／`繼續` | 順暢進入下一個未探索節點 |
| `跳至 M<ID>`／`講 M<ID>` | 非線性跳轉至指定節點，系統自動記住原進度錨點 |
| `跳過` | 不施加負面標籤，導師一句話點破該題核心精要後直接推進 |
| `深入`／`延伸` | 針對當前節點做更極致的實戰邊界或原始碼/理論層級深挖 |
| `調整架構` | 靈活增刪模組或節點，保留既有編號與已記錄筆記 |
| `一次全部給我` | 切換為精簡模式，一次性輸出所有章節精講 |
| `結束`／`匯出` | 進入第三階段，自動編譯輸出 HTML 互動手冊與全量 Markdown 筆記 |

## 🖥️ 第三階段：編譯 HTML 互動手冊

完成學習後，系統將自動調用技能內建的 Python 組裝編譯器：
```bash
python scripts/build_notes.py "learning-notes/<主題>.md"
```

### 產出的 HTML 互動手冊具備以下特色：
- 🔍 **DOM TreeWalker 即時搜尋**：快速過濾章節與內文關鍵字。
- 🧭 **Scrollspy 滾動監聽導覽**：側邊欄目錄隨閱讀進度自動高亮對應章節。
- 🌓 **深淺色主題切換**：自動適應系統主題，支援一鍵切換深色/淺色閱讀模式。
- 🖨️ **@media print 列印排版**：最佳化列印樣式，可直接一鍵另存為乾淨的 PDF 文件。
- 📦 **零外部依賴、完全自包含**：單一 HTML 檔案，離線可直接雙擊瀏覽。

## 📥 安裝與啟用

### 在 Google Antigravity 中使用

#### 方法 1：安裝為全域技能（推薦）
將此 `knowledge-map-learning` 資料夾複製到全域技能目錄：
```powershell
# Windows
Copy-Item -Path "knowledge-map-learning" -Destination "$HOME\.gemini\config\skills\knowledge-map-learning" -Recurse
```

#### 方法 2：在單一專案中使用
將此資料夾複製到你專案目錄的 `.gemini\skills\` 下：
```powershell
Copy-Item -Path "knowledge-map-learning" -Destination "<你的專案路徑>\.gemini\skills\knowledge-map-learning" -Recurse
```
