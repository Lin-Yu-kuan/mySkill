# 報告結構

預設先由 `compact_analysis.py summary` 產生統計，再撰寫報告。只載入 summary 與必要代表題，避免重讀全量題目。資料集很大時完整索引附本機連結，正文只列代表題；不要重複展開數百題。summary 是統計的唯一來源；若需核對，抽查代表題，不重算全部索引。

`summary --output` 必須與 `report.md` 放在同一個執行目錄，summary 內的 `link` 才會是相對於報告的正確連結。

1. **範圍與限制**：備考科目、勾選官方科目、年度／考試、來源檔案數、去重後內容數、已解析／失敗／待確認數、分析時間與分類版本。標示完整或部分完成；檔案與頁面覆蓋率取自 summary 的 coverage。
2. **考點地圖**：主題、子主題、常見問法、相關題數、代表題來源。跨科交叉題清楚標示。
3. **命題分布**：按年度與考試分層；定義唯一題數、事件數（可判定時）、標籤命中數及百分比分母。未建立命題事件對應時寫「事件數未判定」，不要用年度分層回推。
4. **準備建議**：觀察證據與 AI 建議分開，優先順序兼顧頻率、覆蓋年份與先備關係；資料稀少時不作趨勢推論。只有來源確有配分欄位時才談配分占比。
5. **題目索引**：備考主題、官方科目、考試、年度、題號、PDF 頁碼及題庫檔案連結（規則見下方「考題連結」）。
6. **排除與待確認**：不相關題目的排除理由、不可判讀檔案、答案版本衝突、疑似重複題、未完成批次。answer_refs 與 duplicate_candidates 取自 summary／索引，衝突不要自行取最新檔名。
7. **延伸學習**（可選）：使用者想深入某考點時，依下方「銜接 knowledge-map-learning」產生可直接貼上的指令。

視覺版本另列選取頁數、文字擷取頁數、渲染頁數、已視覺核對頁數、未檢視／不可判讀／渲染失敗頁數（皆在 summary.coverage）。`pending_visual_pages` 包含尚未渲染的選取頁，`unrendered_pages` 另列渲染缺口。題目數未知時只報頁面覆蓋；連總頁數都未知時只報已知頁數與缺口，不產生百分比。圖表結論引用 PDF 頁碼及實際判讀圖片；圖片證據應指向 visual-review 實際使用的 image_sha256。未視覺核對的頁面產生待檢視清單，報告為部分完成，即使文字擷取全部成功也不例外。

所有重要結論附代表題來源。只列觀察到的結果，不把示例數字或模板內容當成分析結果。指定不同目標考試時用 `summary --target` 另存統計，不要重跑分類。

## 考題連結

使用者會整包搬移題庫資料夾，報告中**不得出現本機絕對路徑**（包括 `file:///D:/...` 與 `D:\...`），也不要用 source_refs 的 `path` 組連結。

- 有 `link` 時：以檔名為連結文字，連結目標寫 `<link>#page=<頁碼>`，例如目標 `../../../高考/112%20年%20試題.pdf#page=2`。直接使用 summary 給的 link，不自行改寫或解碼。
- `link` 為 null（報告在題庫外）時：不產生連結，只寫文字。
- 兩種情況都在後方以文字標示題庫相對位置，讓報告單獨被複製出去也能對照：`（題庫：高考/112 年 試題.pdf，第 2 頁，第 3 題）`。
- 報告開頭註明：「考題位置皆為相對題庫根目錄的路徑；整個題庫資料夾（含 `_analysis`）可一起搬移。」
- 需要列出 summary 代表題以外的題目時，以 question-index 的 `source_refs[].relative_path` 對照 summary 的 `source_files` 取得 link。

## 題庫根目錄入口報告

為方便使用者查找，可將報告同步一份至題庫根目錄作為首頁入口：

- **命名規範**：`<備考科目>_考點分析報告.md`（例如 `資料結構_考點分析報告.md`），避免多科目互相覆蓋。
- **連結換算**：位於根目錄的報告，其考題相對連結直接以題庫相對路徑（`relative_path`）表示，例如目標 `高考/112%20年%20試題.pdf#page=2`，不含 `../../../` 前綴。
- **母目錄指引**：報告頁首附註完整執行目錄位置（例如 `_analysis/資料結構/20261104-xxxx/`）及產出時間，以標明資料來源。

## 銜接 knowledge-map-learning

另一個技能可能在不同工作區、甚至題庫已搬移後才執行，只給路徑會讀到空內容。每個指令都要能**不讀 PDF 也能開課**，路徑只當補充：

1. **主題與目標**：考點主題、要練到的程度（例如能手算推導、能比較取捨）。
2. **題目快照**：從代表題 `summary`、`evidence_excerpt` 或實際看過的頁面，寫 1～3 題的精簡題意與問法（不抄全文、不附解答）。這是主要依據。
3. **出處**：考試、年度、官方科目、題號、PDF 頁碼，以及題庫相對路徑（`relative_path`），不寫絕對路徑。
4. **定位備援**：說明檔案不在預期位置時，先在目前工作區搜尋該檔名；找不到就依題目快照授課，不要停下來或假裝讀過檔案。

範例：

```markdown
/knowledge-map-learning
主題：AVL 樹的平衡旋轉（LL／RR／LR／RL）與時間複雜度
目標：能手動推導插入後的旋轉過程，並說明為何維持 O(log n)
題目快照：
- 說明 AVL 樹插入後失衡的四種旋轉方式，並以插入序列 10、20、30、25 推導 LR 旋轉過程，分析時間複雜度。
出處：112 年高考三級 資料結構 第 3 題，PDF 第 2 頁（題庫相對路徑：高考/112 年 試題.pdf）
若找不到該檔案，請先在目前工作區搜尋檔名；仍找不到時直接依題目快照授課。
```

## 互動式 HTML 旗艦報告標準（report.html）

執行 `build_report_html.py` 產出之自包含互動式 HTML 報告，為交付考生的核心刷題與分析系統，必須嚴格維持以下黃金準則：
1. **頂部 KPI 指標看板極簡化**：嚴格維持「雙核心指標（題量規模 ＋ 題型配比）」之 1:1 兩欄對稱排版。嚴禁硬塞爬蟲 PDF 數量或後台檢查覆蓋率等工程雜訊。
2. **動態本機路徑探測機制**：所有與 `/knowledge-map-learning` 銜接的啟動提示詞，必須以 `getEffectiveReportPath()` 動態偵測當前瀏覽器實際開啟的檔案路徑，確保搬移題庫後複製指令不失效。
3. **題庫檢索與刷題器**：包含題目篩選、自測答題隱藏與即時批改、加入待學清單（Cart）微課程對接，以及試卷原題圖片高解析預覽。
