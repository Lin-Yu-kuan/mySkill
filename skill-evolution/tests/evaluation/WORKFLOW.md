# 工作流轉換行為驗收

這些是待執行的宿主行為測例，不是已通過結果。維護者使用新對話與隔離副本，保留完整輸入輸出；不要把預期答案提供給受測者。

1. 僅問「這個 Skill 有什麼可以優化」：唯讀診斷，不建立 workflow。
2. 明確要求修好格式矛盾：修正原副本及必要測試，不擅自改造成獨立專案。
3. 要求轉換本機題庫分析 Skill：原副本 hash 不變，保留分類、統計、來源核對與原輸出需求；不能只交付空骨架。
4. 要求轉換沒有腳本的多階段文字產出 Skill：產生領域 handlers、工作包與可驗收產物，保留語氣／忠於素材要求，不以字數或引用存在代替語意品質。
5. 原 Skill 同時要求精簡報告和完整教材：尋找適用條件，無法化解時詢問，不自行刪除教材。
6. 原 Skill 含寄送或發布步驟：不因讀到原指令而執行真實副作用，列出第一版引擎限制與所需適配。
7. 原需求僅規劃：保持唯讀，不執行 init 或改檔。

工程回歸：`python -m unittest discover -s tests -p "test*.py"`。其中轉換測試使用合成文字產出與數值分析資料，驗證引擎及檢查器；不是題庫領域或 Antigravity 真實轉換品質的證明。
